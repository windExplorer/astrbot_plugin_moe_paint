# 萌萌绘卷（astrbot_plugin_moe_paint）

> 让 bot **自己挑题材、自己写提示词、定时画成卷**：LLM 负责「画什么、怎么画」，ComfyUI 负责画，
> 白名单会话负责收，插件内置的图库 WebUI 负责把每一张连同「创作简报 / 提示词 / 失败原因」一起记下来。

- 适用：AstrBot `>= 4.28`，一个可访问的 ComfyUI 服务器（本地或中转站均可）。
- 许可证：AGPL-3.0（ComfyUI 客户端改编自同作者的 `astrbot-comfyui-anima`，同源署名见 `comfy_client.py` 文件头）。
- 作者：云端之风 <1479221500@qq.com>（windExplorer）

## 一、它能做什么

| 能力 | 说明 |
| --- | --- |
| 定时自动出图 | 两种节奏：**按间隔**（每 N 分钟 / 小时 / 天，可加随机浮动）或**每天固定时刻**（如 09:30、20:00） |
| 多样性提示词 | 插件先分层抽签（类别 → 题材 → 风格 → 构图 → 光色 → 氛围），LLM 只把「创作简报」写成提示词，避免千篇一律的美少女半身像 |
| 题材权重 | 每个类别可设权重（默认偏向少女题材：动漫少女+美少女 约 53%、真人少女 约 18%，动漫:真人 ≈ 3:1），其余类别保底参与；改权重即改画风倾向 |
| 尺寸白名单 | LLM 不报数字宽高，只按构图朝向从工作流模板的尺寸预设里取值（16 对齐） |
| 工作流轮换 | 多份 ComfyUI API 格式工作流，随机或按顺序轮换；顺序**可见**（编号链 / 下一张）、**可排**（上下移）、**不跳位**（记上一张是谁）；节点定位自动完成，异形链路可手工覆盖 |
| 工作流上传解析 | 在控制台**拖拽 / 选择 / 粘贴** JSON，上传即解析（正负向、尺寸、seed、保存节点、底模），解析不过直接拒绝入库 |
| 用萌绘的工作流 | 一键把工作流来源切成「跟随萌绘」，直接用萌绘里配好的工作流（含它设的采样器/放大/保存覆盖），不必两边各维护一份 |
| 提示词按底模适配 | 自动识别底模家族（Anima / Flux / Qwen / SD3 / 写实…），决定用英文标签、中文还是英文自然语言，顺带切尺寸档与质量词；识别不到才用你填的值 |
| 可画类型 + 画风硬锚定 | 每条工作流单独设「只画动漫 / 只画真人 / 两者皆可」（默认按底模自动判断），既按类型筛题材，**也把画风真正写进提示词**：简报带可画类型、系统提示词加硬规则、出图前硬拼动漫/写实标签与排除词；风景星空等题材也跟着画风走。跟随萌绘时可逐条设 |
| 人物锚定 | 默认把人物限定为东亚面孔的年轻成年女性；少女 / 写真 / 角色类固定前置人物标签，**排除负面词对所有类别生效**（挡住老人、男性、儿童），景物类不塞 `1girl` 以免毁风景 |
| 系统提示词可定制 | 可追加自定义规则，或按三种提示词风格完全替换系统提示词；JSON 输出契约始终保留，改不坏 |
| 角色名单 | 内置通用角色原型，另有一份可删改的知名动漫 / 游戏角色名单（配置里改，删行即停用） |
| 静默投递 | 生成完直接发到白名单会话（`StarTools.send_message`，不走事件管线，不触发其他插件） |
| 生成记录图库 | 每轮（含失败）全量落库；图片按 sha256 内容寻址归档（跨月也复用同一份），容量超限按最旧淘汰，收藏永不淘汰；被淘汰的记录会标记「图已清理」而不是留一张打不开的破图 |
| 控制台 WebUI | 总览 / 图库 / 调度 / 投递 / 生成服务 / 工作流 / 主题词池 / 提示词 / 关联萌绘 / 调试，十个页面 |
| 关联萌绘 | 可选：直接复用 **ComfyUI萌绘** 里配好的 ComfyUI 服务器地址，免去两处填同一个 URL |
| 提示词清洗与负面基线 | 解权重 / 转义括号 / 去重 / 去画师名 / 标签预算，禁词自动进负向；英文线与中文线各一套负面基线，LLM 给空串也有兜底 |
| 镜头 / 成品形态 | 写真线多抽一层镜头（85mm f/1.8…），动漫线多抽一层成品形态（立绘 / 封面 / 壁纸） |
| 画质闸门 | 空图体检（全黑/纯色直接判失败并重试）、成图自检打分、低分换种子重画、连拍选优（只投最好的） |
| 精修 pass | 出图后放大 1.5× + 低 denoise 重绘（内置标准工作流，不碰你的模板） |
| 重画与收藏 | 图库任一记录可「同 seed 重画 / 换 seed 变体」，也可把提示词收藏起来反复用 |
| 采样参数档 | 每条模板可选 keep / 快出 / 标准 / 精修，只覆盖采样器上真有的字段 |
| 时间一致性 | 按纬度 + 月份估算日出日落，光照词池按时段收窄、系统提示词写时段硬规则、出图前扫描「深夜写正午烈日」并纠偏重写 |
| 角色卡 | 一张卡 = 固定标签 + 排除词，让同一角色跨图一致；支持随机 / 固定 / 指令 `--char` 指定 |
| 提示词 A/B | 两套附加规则按 A→B 轮换，配合成图自检的平均分比较哪套更好 |
| 调试工具 | ComfyUI 连通性与队列、LLM 试跑（看简报 / 可画类型 / 时段 / 角色 / 标签数 / 最终正负向提示词 / 原始返回 / 耗时）、投递自检、内存事件日志 |

## 二、和 ComfyUI萌绘（astrbot-comfyui-anima）的关系

**不取代、不强依赖**：萌绘管「人叫它画」，绘卷管「自己定期画」。

- 绘卷直连 ComfyUI 的 HTTP API（`/prompt`、`/history`、`/view`、`/queue`），**不调用**萌绘的绘图接口 —— 萌绘升级不会把绘卷一起弄坏。
- 可选联动：在「关联萌绘」页开启 **跟随萌绘的服务器** 后，绘卷每次出图都现读萌绘当前启用的那台 ComfyUI 地址；萌绘换地址，绘卷自动跟上。
- 两边共用同一台服务器时，绘卷的 **队列避让**（`comfyui.queue_defer_threshold`，默认 2）会在提交前查远程队列，前方任务多就顺延 5 分钟，给萌绘的交互出图让路。
- 工作流模板、图库、提示词风格、模型配置**各自独立**，互不读写。

## 二·五、工作流从哪来（三种方式，任选）

配置项 `workflow_source` 决定用哪套：

**1）控制台上传（推荐，独立于萌绘）**

「工作流模板」页 → 把 ComfyUI「**导出 (API)**」得到的 `.json` 拖进上传区（或粘贴内容）→ 点「解析预览」看解析结果 → 「确认入库」。
入库时会自动：

- 校验是否 API 格式（界面格式会明确提示去导出 API 版）；
- 定位正向/负向文本节点、latent（尺寸）节点、seed 节点、保存节点，并读出底模文件名；
- **拒绝**图生图链路（latent 没有 width/height，本插件只管文生图）；
- 落盘到 `workflows/<模板名>.json`（同名覆盖），并写入模板清单。

**2）手动丢文件（无 WebUI 时）**

把 JSON 放进 `data/plugin_data/astrbot_plugin_moe_paint/workflows/`，再到清单里登记一行（名称 + 文件名）。首启已自带 `anima_t2i.json`。

**3）跟随萌绘（`workflow_source = anima`）**

「工作流模板」页把来源切成「跟随萌绘」→ **多选**几条萌绘的工作流（也可一条不选 = 全部可用）→ 保存。此后每次出图：

- 从参与名单里按「模板轮换」（随机 / 顺序轮换）挑一条；顺序轮换时**名单填写顺序即出图顺序**（见「七·七」）；
- 现读那条萌绘工作流（`base_id` 关联的基础工作流 + 它配的采样器/步数/CFG/放大/清理/保存覆盖）；
- 用萌绘解析好的注记定位注入点（异形链路也能认），再注入本插件抽签得到的提示词与尺寸；
- **不写萌绘任何配置**，只读。

> 萌绘的旧版工作流（没有关联基础工作流）或基础工作流解析没通过的，列表里会标「不可用」并给出原因。
> 尺寸默认 `anima.size_preset = follow`：直接用基础工作流 latent 的宽高（横竖互换），可用 `sdxl`/`flux`/`sd15` 改回白名单。
> 跟随萌绘时也能**逐条设可画类型**：在控制台「工作流模板」页的「轮换顺序」列表里，每条都有一个下拉
> （跟随整体设置 / 自动判断 / 只画动漫 / 只画真人 / 两者皆可），结果写进 `anima.workflow_scopes`。
> 没单独设置的回落到 `anima.subject_scope`（默认 `auto` 按各条底模推断）。改完点「保存」。

## 三、安装

1. 把 `astrbot_plugin_moe_paint` 目录放到 AstrBot 的 `data/plugins/` 下（或用插件市场 / 上传 zip 安装）。
2. 确认依赖已装：`pip install -r requirements.txt`（只有 `aiohttp` / `aiosqlite`；`Pillow` 可选，装了缩略图更快更小）。
3. 在 AstrBot 后台「插件管理」里启用，然后：
   - 打开插件配置，填 **ComfyUI 服务器地址**（或去「关联萌绘」页跟随萌绘）；
   - 选一个 **提示词模型**（留空 = 全局默认对话模型）；
   - 设置调度（默认每 6 小时、再随机晚 0~30 分钟，安静时段 01:00–08:00，每日上限 4 张）。
4. 打开插件页「萌萌绘卷 · 控制台」，在「总览」点 **立即画一张** 验证整条链路。

> 首次启动会把内置起步工作流 `builtin/anima_t2i.json` 复制到
> `data/plugin_data/astrbot_plugin_moe_paint/workflows/`，开箱即可出图。
> 用别的模型/工作流时，把 ComfyUI「导出 (API)」得到的 JSON 丢进同目录，再到控制台「工作流模板」登记。

## 五、控制台（WebUI）

插件页按「左侧导航 + 右侧内容」组织，十个页面：

| 页面 | 内容 |
| --- | --- |
| 总览 | 下次生成倒计时、今日 / 累计 / 成功率、最近的图与事件、工作流健康、立即画一张 |
| 图库 | 状态 / 工作流 / 类别 / 关键词 / 只看收藏筛选；网格缩略图（带质检分）；详情抽屉（全元数据、复制提示词与 seed、收藏、重投、**同 seed 重画 / 换 seed 变体 / 试评分**、收藏提示词、删除）；顶部**提示词收藏**卡片；**全屏看大图**（滚轮缩放 / 拖动 / ←→ 切换 / Esc 关闭）；有新增记录时自动刷新 |
| 调度计划 | 图形化设置：模式二选一（间隔 / 每天时刻）、间隔单位换算、安静时段开关、每日上限开关、保存即重算下次计划 |
| 投递 | 会话名单（UMO，每行一个）、附带文案开关与模板、发测试消息 |
| 生成服务 | ComfyUI 地址与等待预算、队列避让阈值、提示词模型与超时、图库容量、管理员通知 |
| 工作流模板 | 顶部「轮换顺序」卡（编号链 / 下一张 / 从 #1 重置 / 手动占位开关）；模板清单编辑（名称 / 文件 / 标签风格 / **可画类型** / 尺寸预设 / 默认负面词 / 启用）、**↑↓ 调整轮换顺序**、校验状态、节点覆盖项；跟随萌绘时「轮换顺序」列表每条可单独设可画类型 |
| 主题词池 | **一张题材清单**：每行的启用开关 / 权重 / 可画类型标签 / 题材数，展开可看内置题材并追加词、新增自定义类别；**角色卡**（固定标签 + 排除词，可增删改）与角色名单各一张卡片，风格·光色·氛围·构图与可画类型覆盖收进「高级」 |
| 提示词 | 人物锚定规则与硬约束、**画风硬锚定开关**、负面基线与标签清洗、A/B 测试、自定义规则（追加）、三套系统提示词完全覆盖（高级）、生效预览、跳调试试跑 |
| 关联萌绘 | 萌绘是否安装与版本、服务器列表（只读）、跟随 / 复制地址 / 关闭跟随、连接测试 |
| 调试与日志 | 运行环境快照、ComfyUI 连通性与队列、LLM 试跑、投递自检、事件日志（**每 3 秒自动刷新**） |

### 调度页的三个「开关」约定

用户明确要求：**停用某项功能用开关，不要靠清空输入框**。

- **安静时段**：右上角开关关掉后，时间设置原样保留但一律不生效（下次打开立即恢复原时间），不会再出现「清空了时间以为关了、其实还在跑」或反过来的困惑。
- **随机浮动**：关掉即准点，分钟数保留。
- **每日上限**：关掉即不限张数（等价于 0，但不用记住这个约定）。

### 间隔的基准是「上一张」

- 下一次计划 = **上一张的开始时刻 + 间隔**（不是「出图结束时刻 + 间隔」，也不是「保存配置的时刻 + 间隔」）。
  所以画一张花 5 分钟，周期仍然是 6 小时，不会被拉长；改间隔也不会白等一整个新周期。
- 算出来已经过期（间隔调短、插件停机很久）→ 立刻画这一张，然后继续按新间隔排。
- 重启后从库里取最近一条记录的开始时间续算，不会从启动时刻重新等。
- `daily`（每天固定时刻）例外：过了就等下一个时刻，不补画。

## 六、配置项速查（`_conf_schema.json`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 调度总开关（关掉后手动「立即画一张」仍可用） |
| `comfyui.url` | `http://127.0.0.1:8188` | ComfyUI 地址（开启跟随萌绘时此项不生效） |
| `comfyui.draw_timeout` | `180` | 单张基础等待（秒） |

| `comfyui.hard_cap` | `600` | 等待硬上限（秒） |
| `comfyui.poll_interval` | `2` | 轮询 `/history` 的间隔（秒） |
| `comfyui.queue_defer_threshold` | `2` | 定时出图前查队列，前方 ≥ N 个任务就顺延 5 分钟；`0` = 关闭避让 |
| `llm.provider_id` | 空 | 指定提示词用的提供商 id；空 = AstrBot 全局默认 |
| `llm.timeout` | `45` | LLM 调用超时（秒） |
| `prompt.persona_enabled` / `persona_text` | `true` / 内置规则 | 人物锚定开关与规则文本（东亚面孔的年轻成年女性；写进三种系统提示词） |
| `prompt.persona_tags` / `persona_negative` / `persona_negative_zh` | 见 schema | Danbooru 固定前置的人物标签、英文 / 中文排除负面词（挡其他人种、中老年、未成年） |
| `prompt.extra_rules` | 空 | 追加到三套系统提示词的自定义规则，输出契约始终保留；改「画什么 / 别画什么」用这个 |
| `prompt.style_anchor_enabled` | `true` | **画风硬锚定总开关**：开启后工作流的可画类型会写进简报与系统提示词、并在出图前硬拼画风标签 / 排除词；关闭则退回 v0.7.5（可画类型只筛题材） |
| `prompt.override_danbooru` / `override_natural` / `override_natural_en` | 空 | 高级：完全替换对应风格的系统提示词；文本里没写 JSON 输出契约会自动补上 |

| `prompt.banned_tags` | 空 | 禁词：从正向剔除并自动写进负向（仅 danbooru） |
| `prompt.strip_artists` | `true` | 剔除 `artist:xxx` / `by xxx`（仅 danbooru） |
| `prompt.max_tags` | `75` | 正向标签上限，超出按「主体/外观优先」截断；`0` = 不限 |
| `schedule.mode` | `interval` | `interval` 按间隔 / `daily` 每天时刻 |
| `schedule.interval_minutes` | `360` | 距**上一张开始时刻**的间隔（分钟，最低 1） |
| `schedule.jitter_minutes` | `30` | 间隔上随机追加 0~N 分钟；`0` = 不浮动 |
| `schedule.daily_times` | `09:30,20:00` | daily 模式的时刻表（逗号分隔） |
| `schedule.quiet_enabled` | `true` | **安静时段开关**（关掉后 `quiet_hours` 自动失效） |

| `schedule.max_per_day` | `4` | 每日定时出图上限；`0` = 不限 |

## 七·五、提示词如何适配底模

不同底模吃的东西完全不一样，插件默认**按工作流里的底模文件名自动判断**（模板里 `prompt_profile = auto`）：

| 底模家族 | 识别关键词（文件名，小写包含） | 提示词风格 | 尺寸 | 质量词 |
| --- | --- | --- | --- | --- |
| 动漫标签系 | anima / illustrious / noob / pony / animagine / anything / counterfeit / hassaku … | `danbooru` 英文标签 | 沿用模板 | 自动加 `masterpiece, best quality, very aesthetic, absurdres` |
| Flux | flux / schnell / kontext | `natural_en` 英文自然语言 | flux（1344×768 等） | 不加 |
| Qwen-Image | qwen | `natural` 中文自然语言 | qwen（1664×928 / 1328²） | 不加 |
| SD3.x | sd3 / sd_3 | `natural_en` | sdxl | 不加 |
| 写实 SDXL | realvis / juggernaut / realistic / chillout / majicmix … | `natural_en` | sdxl | 不加 |
| 认不出来 | 其它 | **用模板里手填的兜底值** | 手填 | 不加 |

- 想强制某种风格：把模板的「提示词适配」从「自动」改成具体风格即可（此时标签风格下拉才可编辑）。
- 跟随时萌绘时的优先级：**萌绘底模库的「提示词风格 / danbooru 适配」** → 底模文件名 → 模板兜底；
  尺寸优先 `follow`（用基础工作流 latent 的宽高）。
- 自动改动会在模板行显示「生效：底模画像 Flux · 提示词 natural_en · 尺寸 flux」，并与原填写值对照，
  不会悄悄改你的配置。
- 质量词只在 danbooru 风格下补，且模型自己写了 `masterpiece`/`best quality` 就不重复。

## 七·六、题材倾向与可画类型（默认少女向，可随时改）

内置 **11 个类别**，「少女」拆成动漫 / 真人 / 写真 / 角色几条线，各线题材池与风格池不同：

| 类别 | 内容 | 风格池 | 需要的可画类型 |
| --- | --- | --- | --- |
| 美少女 / 动漫少女 | 二次元少女日常、插画化的樱花回眸与祭典浴衣 | 动漫系 | `anime` |
| 动漫角色 / 游戏角色 | 通用角色原型（魔法少女、巫女、弓手、法师） + 可删改的知名角色名单 | 动漫系 | `anime` |
| 真人少女 / 写真摄影 | 自然光写真、居家白衬衫、泳池清爽泳装、旅拍、影棚柔光、胶片街拍 | 摄影系 | `photo` |
| 人物肖像 | 老画师的手、萨克斯手、老船长（**不套少女人物标签**） | 摄影系 | `photo` |
| 风景场景 / 宇宙星空 / 艺术创意 / 自然生态 | 纯景物与创意题材（**不套少女人物标签**） | 全局 | `both` |

默认权重 `美少女=5, 动漫少女=4, 真人少女=3, 写真摄影=2, 动漫角色=1, 游戏角色=1, 其余各 1`，
少女相关合计约 76%，其余类别保底多样性。

**可画类型闸门**：每条工作流有 `subject_scope`（默认按底模自动判断），抽签时先按类型筛类别再加权——
只画动漫的工作流只抽 `anime` + `both`，只画真人的只抽 `photo` + `both`，两者皆可不限制。
所以「写真 / 泳装」不会被派给动漫底模，「二次元角色」不会被塞给写实底模。

**画风硬锚定（v0.7.6 起，默认开启）**：可画类型不只是筛题材，还会一路传到提示词，
不依赖 LLM 自觉：

| 环节 | 只画动漫 | 只画真人 |
| --- | --- | --- |
| 创作简报 | 加「可画类型=只画动漫（二次元插画）」 | 加「可画类型=只画真人（写实摄影）」 |
| 系统提示词 | 三套风格各追加「必须是 2D 动漫插画、禁止写实照片」 | 对称追加「必须是写实摄影、禁止二次元」 |
| 风格池 | 一律动漫风格池 | 一律摄影风格池 |
| 最终 prompt | Danbooru 前置 `anime style, 2d, illustration`；自然语言风格句首点明「二次元动漫插画」 | 前置 `photorealistic, photograph`；句首点明「写实摄影作品」 |
| 最终 negative | 追加 `photorealistic, photo, 3d render, live action…` | 追加 `anime, cartoon, illustration, 2d…` |

**风景 / 星空 / 艺术 / 生态不是中性画风**：设了只画动漫，它们也画成动漫插画；
设了只画真人，它们也画成写实摄影。这解决了「设了只画动漫，却因为抽到『胶片摄影颗粒感』
而画出真人照片」的问题。人物排除负面词（老人 / 男性 / 儿童等）对**所有类别**生效，
但景物类仍不会硬塞 `1girl`，避免毁掉风景。关掉「提示词」页的「画风硬锚定」开关
即可退回 v0.7.5 行为（可画类型只筛题材）。

**怎么给单条工作流设**（四选一：`auto` 自动判断 / `anime` 只画动漫 / `photo` 只画真人 / `both` 两者皆可）：

| 来源 | 位置 |
| --- | --- |
| 本插件工作流库 | 「工作流模板」→「模板清单」→ 每行的「可画类型」下拉；上传表单里也有 |
| 跟随萌绘 | 「工作流模板」→「轮换顺序」列表 → 每条的下拉（写进 `anima.workflow_scopes`）；没单独设的回落到来源卡的「可画类型（整体默认）」 |

每行的「生效：…」会显示最终生效值，`auto` 被推断成了什么一目了然。
注意它**不会换底模**：如果某条工作流用的本来就是写实底模（`提示词适配 = natural_en`），
标「只画动漫」也变不出二次元；模板行会给出错配提示，建议换动漫底模
（`提示词适配 = danbooru`）。提示词语言由「提示词适配」决定，与可画类型是两条独立的线。

方向相反的配置：给**题材类别**标它需要什么底模，在「主题词池 → 高级 → 类别可画类型覆盖」
写 `类别=anime|photo|both`，主要给自定义类别用。

调整方式：控制台「主题词池」页的**题材清单**，每行直接改：

- 关开关 = 整类不画（写进 `theme.disabled_categories`，优先级高于权重）；
- 改权重 = 抽中概率，下面实时显示各类百分比与「少女相关合计」；
- 「少女向预设 / 均衡预设」两个一键按钮；
- 展开行 = 看内置题材、追加自己的词；底部可新增自定义类别；
- 角色名在「动漫 / 游戏角色名单」卡片里删改，删掉整行即停用该类角色名。

> 安全边界：涉及泳装与室内写真的题材一律写成成年、生活化、自然光的日常表达；
> 人物锚定会强制成年化并在负面词里排除未成年，请勿用于生成未成年人不当内容。

## 七·七、轮换顺序（顺序是什么 / 怎么排 / 下一张是谁）

**顺序的定义**：`workflow_selection = round_robin` 时，顺序就是**可用模板（已启用且校验通过）的清单顺序**：

- 本插件库：控制台「工作流模板」页的模板清单**从上到下**（用每行右侧 ↑↓ 调整），上传新模板追加到末尾；
- 跟随萌绘：`anima.workflow` 名单**从上到下**（在「参与轮换的萌绘工作流」下的「轮换顺序」列表里 ↑↓ 调整）。
  名单为空时按萌绘自己的列表顺序参与，点「固定当前顺序以便排序」即可固化成名单再调。

> v0.7.4 之前 `anima.workflow` 只是个「参加 / 不参加」的集合，勾选顺序不影响轮换，很容易误解。

**看得见**：「工作流模板」页第一张卡就是「轮换顺序」，显示 `#1 A → #2 B → #3 C ↻` 并高亮
「下一张：#N 名字」；模板清单每行也有「轮换 #N」标签。随机模式下卡片会说明「当前没有固定顺序」。

**推进规则**（v0.7.4 起）：

| 事件 | 是否推进到下一张 |
| --- | --- |
| 定时出图成功 | 是 |
| 定时出图失败 | 否（下一轮仍是这一条，方便看出它一直失败） |
| 「立即画一张」/ `/绘卷 画一张` 成功 | 默认**否**；`rotation_manual_advances = true` 才推进 |
| 插件重启 | 不重置，从库里读上次进度续轮 |

游标存在 `moe_paint.db` 的 meta 表中，记的是**上一张模板的稳定标识**（本插件库用文件名，
萌绘工作流用它自己的 id），不是「第几张」。所以停用 / 新增 / 某条校验失败导致可用池变化时，
下一张仍是「上一张在现池里的下一条」，不会整体错位；上一张被删掉则从 #1 可预期地重新来过。
升级时若库里只有旧版的整数 `rr_cursor`，第一轮会按它续上，之后自动切到新游标。

「从 #1 重置」按钮清空进度；「手动出图也占一个轮换位」开关也在轮换顺序卡上，改完点保存。

## 七·八、画质流水线（v0.7.8）

一轮出图的完整链路，画质相关的每一环都能单独关掉：

```
抽签（含镜头/成品形态） → LLM 写提示词 → 标签清洗 → 人物/画风锚定
→ 质量词 + 负面基线 → 注入（文本/尺寸/种子/采样参数）→ 出图
→ 空图体检（全黑/纯色直接判失败，换种子重试一次）
→ 精修 pass（可选：放大 1.5× + 低 denoise 重绘）
→ 成图自检（可选：多模态打分）
→ 连拍/低分重画（可选）→ 只投递分数最高的那张 → 归档入库
```

**1）提示词清洗（danbooru 风格，默认开）**

| 处理 | 为什么 |
| --- | --- |
| 解 `(tag:1.2)` 权重 | LLM 爱写权重，标签系底模不认，还占 token |
| 括号转义 `\(` `\)` | CLIP 把 `()` 当权重语法，角色 tag `hatsune miku (vocaloid)` 会被算坏 |
| 去重 / 下划线转空格 / 去画师名 | `artist:xxx`、`by xxx` 是模型最常见的违规 |
| 按 `prompt.max_tags` 截断 | SD1.5 的 CLIP 只有 77 token，超出的完全不生效 |

**2）负面基线**：`prompt.negative_base_en` / `negative_base_zh` 永远垫在最前，
LLM 给空串时也有质量兜底（英文线给 danbooru 与 natural_en，中文线给 natural）。
`prompt.banned_tags` 里的词会从正向剔除并**自动写进负向**——只删不加等于没管住。
`prompt.quality_extra` 追加在自动质量词后面。

**3）镜头 / 成品形态层**：写真线多抽一层「镜头」（85mm f/1.8 浅景深…），
动漫线多抽一层「成品形态」（角色立绘 / 轻小说封面 / 壁纸构图…）；抽到就写进简报，
由 LLM 转成目标语言。

**4）采样参数档**（「工作流模板」页每条模板）：`keep` 沿用 JSON 原参数；
`fast` 20 步 CFG5 / `standard` 28 步 CFG6 / `high` 36 步 CFG6.5。
只覆盖采样器节点上**真实存在**的字段，写不进去会在模板行给警告（不会静默失效）。

**5）空图体检**：ComfyUI 在底模/VAE 不匹配时常常不报错，而是返回一张全黑 PNG。
现在会算像素分布，全黑/全白/纯色/过小直接判失败并换种子重试一次，理由写进记录。

**6）精修 pass**（`refine.*`，默认关）：出图后上传回 ComfyUI，走插件内置的一份标准
精修图（独立检查点加载器 → 放大 → VAEEncode → KSampler denoise 0.35 → 保存）。
不碰你自己的模板；失败自动用原图。**必须填 `refine.ckpt_name`**，否则自动跳过。

**7）成图自检**（`quality_guard.*`，默认关）：用支持图片输入的模型给成品打分
（结构崩坏 / 清晰度 / 与描述相符 / 完成度），分数落库、图库能看、能筛。
低于 `min_score` 会用**同一份提示词换种子**重画（`retry` 次）；
`shots > 1` 时连拍多张，只投递分数最高的那张，其余留在图库可手动重投。
阈值拿不准：图库详情里点「试评分」看实际分数再回来调。

**8）重画与收藏**（图库详情）：
「同 seed 重画」几乎复现，「换 seed 变体」同一提示词换种子；
「收藏此提示词」存进收藏夹，图库顶部「画一张」可反复用（都是跳过 LLM 直接出图）。

**指令开关**：`/绘卷 画一张 少女 --no blurry,watermark --ratio 3:2 --seed 42`，
还支持 `--style 胶片摄影颗粒感`；控制台「立即画一张」的主题词也认这套写法。

## 七·九、时间一致性 / 角色卡 / A-B（v0.7.9）

**1）时间一致性**（`time_sense.*`，默认开）

用「纬度 + 月份」按太阳赤纬估算日出日落（`daylight.py`，纯标准库），把当前时刻折成
六个时段：深夜 / 黎明 / 上午 / 白天 / 黄昏 / 入夜。三件事随之改变：

| 环节 | 效果 |
| --- | --- |
| 光照词池 | 深夜只抽月光 / 霓虹 / 星云 / 极光 / 烛火；想随时画白天就关掉 `sync_light` |
| 系统提示词 | 追加一条硬规则（「时段是深夜，画面必须是夜间光照，禁止正午烈日」），三套提示词与「完全覆盖」都会带上 |
| 出图前扫描 | 深夜却写「正午烈日」这类矛盾会被抓出来，带原因让模型重写一次（`guard_retry`，只在命中时才多一次调用） |

纬度只影响日出日落几分钟：北京 39.9 / 上海 31.2 / 广州 23.1。整套可以一键关掉，
关掉后行为与 v0.7.8 完全一致。

**2）角色卡**（`character.*` + 「主题词池」页的角色卡卡片）

一张卡 = 角色名 + 别名 + 固定标签 + 排除词。开启后：

- 名字写进创作简报（LLM 知道画谁），danbooru 风格把固定标签**前置**进提示词；
- 排除词并入负向（挡住「画成别人」的常见描述）；
- 自然语言风格不插标签串（会破坏句子），只靠简报里的角色名。

三种用法：`mode=random` 每轮抽一张 / `mode=fixed` 固定某张 / 指令
`/绘卷 画一张 --char 初音未来` 临时指定（优先于配置）。

**3）A/B 测试**（`prompt.ab_*`）

两套「附加规则」按 A→B 轮换追加到系统提示词末尾，用哪一版会记进记录。
配合成图自检，总览「平均质检」会显示 `A 78.2（12） B 74.9（12）` 这样的对比；
`/stats` 的 `by_ab` 字段也能拿到（只统计有分数的样本）。
A 和 B 都填才生效，且最好只改一个变量，否则比不出结论。

## 八、提示词工程（为什么不容易「画腻」）

1. **分层抽签**：类别、题材、风格、构图、光色、氛围每层独立随机 → 组成一句「创作简报」。
   类别按 `theme.category_weights` 加权（默认少女向），且**风格池随类别收窄** ——
   动漫少女/美少女只抽动漫风格（赛璐璐、厚涂、新海诚…），真人少女/人物肖像只抽写真风格
   （胶片颗粒、自然光人像、电影感浅景深…），避免「二次元题材配胶片颗粒」这类错配。
2. **LLM 只做转写**：系统提示词按模板生效的提示词风格切换（`danbooru` 英文标签串 / `natural` 中文自然语言 / `natural_en` 英文自然语言，见上一节自动适配），要求严格输出 `{"prompt","negative","caption"}`；不合契约会带原因重试一次。
   控制台「提示词」页可追加自定义规则（`prompt.extra_rules`），或按风格完全替换系统提示词
   （`prompt.override_*`）；**输出契约段始终保留**，替换文本没写 JSON 契约会自动补上。
   「生效预览」能直接看到三种风格下 LLM 真正收到的文本。
3. **尺寸不由模型定，但每张都不一样**：当次抽到的构图决定朝向（横/竖/方），再按构图类型在
   该朝向的白名单里匹配长宽比 —— 超广角/全景/俯瞰取最横，全身像取最瘦高，特写/半身像偏 3:4，
   对称/留白取正方形；相邻档位会小概率参与随机，避免同一构图永远一个数值。
   跟随萌绘 + `size_preset = follow` 时改为严格沿用基础工作流 latent 的分辨率（横竖互换、方图取短边）——
   想看尺寸随构图变化，请改用 `sdxl` / `flux` / `qwen` 预设。
4. **可调词池**：控制台「主题词池」一张题材清单里可停用整类、调权重、追加题材、新增自定义类别；
   风格 / 光色 / 氛围 / 构图四层与可画类型覆盖收在「高级」里。
5. **可画类型先于抽签**：当次工作流的 `subject_scope` 会先筛掉它画不了的类别、并把风格池
   收窄到对应画风，再按权重抽（见上一节）。
6. **人物锚定**：系统提示词写人物规则；Danbooru 风格对少女 / 写真 / 角色类固定前置
   `1girl, solo, asian, young adult woman` 等标签；**排除负面词（其他人种 / 中老年 / 男性 /
   未成年）对所有类别生效**，景物类不加正面人物标签以免毁风景。整套可在「提示词」页改或关。
7. **画风硬锚定（默认开）**：可画类型会写进创作简报与系统提示词，LLM 返回后再直接改字符串——
   Danbooru 前置画风标签、自然语言风格句首点明画风，负向词追加反向画风排除词；
   完全覆盖系统提示词时画风硬规则仍会追加。这样「只画动漫」不再只是一句空话。
   可在「提示词」页用「画风硬锚定」开关关掉。

## 九、排障

| 现象 | 先看哪里 |
| --- | --- |
| 到点没出图 | 「总览」的「当前计划」与「最近事件」；再核对总开关、是否暂停、是否在安静时段、是否达每日上限 |
| 「下次生成」停在过去不动 | 出图期间计划点不会推进（要等画完才排下一轮）：v0.7.1 起会显示「正在生成 · 已 N 分」。若**没有**显示生成中而时间一直过期，看「调试与日志」的事件日志排查；单轮超过 30 分钟会被强制判失败 |
| 一直失败 | 「图库」筛选状态=失败看错误（v0.7.0 起会写明 ComfyUI 的节点与字段级原因）；或「调试」页 LLM 试跑看契约是否合规 |
| 失败理由是空的 | 老记录（v0.7.0 之前写的）可能没有原因；插件重启留下的「生成中」会在下次启动时自动收尾成失败并写上「生成被中断」。新记录不会再有空白理由 |
| 图库里某条显示「已按容量清理」 | 那张图超过 `gallery.max_total_mb` 被 LRU 淘汰了（提示词/种子/简报仍在，方便复现）。调大上限、或给重要图点★（收藏永不淘汰） |
| 一直停在「生成中」不动 | v0.7.7 起调度循环每 10 分钟兜底扫一次：超过 35 分钟还没结果的记录会自动收尾成失败并写明原因。若刚重启仍显示生成中且不足 35 分钟，等扫描即可 |
| ComfyUI 连不上 | 「调试」页 ComfyUI 连通性（含队列）；核对地址是否含 `http://`；跟随萌绘时看萌绘里的服务器是否可用 |
| 模板校验失败 | 「工作流模板」页红字提示；多为缺 JSON 文件，或异形采样链路需要填节点覆盖 |
| 上传被拒绝 | 预览区会写具体原因：界面格式（要「导出 (API)」）/ 找不到正向或 latent 节点 / 图生图链路暂不支持 / 节点缺 class_type |
| 跟随萌绘后出图失败 | 失败记录会写「跟随萌绘模式：…」的具体原因；多半是萌绘那条工作流用的底模/自定义节点在那台服务器上不存在，或萌绘里那条本来就没解析通过 |
| 投递收不到 | 「投递」页发测试消息；UMO 平台 id 必须与适配器实例一致（`platform id ≠ 适配器类型名` 是最常见坑） |
| 改了配置没生效 | 调度相关保存后会自动重算下次计划；其他配置下一次出图即生效（每轮现读配置） |
| 某类题材从来不出 | 「主题词池」看实时分布与启用开关；若模板是动漫底模，写真 / 角色类会被可画类型闸门挡掉，改用「两者皆可」的工作流或改模板的可画类型 |
| 人物总是欧美脸 / 年龄偏大 | 「提示词」页确认人物锚定已开启并点过保存；要改人设就编辑人物规则、固定标签与排除负面词 |
| 改完系统提示词后每轮都失败 | 「提示词 → 生效预览」看是否还带 JSON 输出契约；完全替换时请自己要求模型返回 `{"prompt","negative","caption"}` |
| 顺序轮换看起来跳了一张 | 看「工作流模板」第一张「轮换顺序」卡的「下一张」；失败轮与手动试画（默认）不占位，若开了手动占位开关则手动出图也会推进 |
| 改了清单 / 名单顺序没生效 | 保存后下一张起生效；点轮换顺序卡的「刷新」重新读；跟随萌绘时先「固定当前顺序以便排序」再上下移 |
| 跟随萌绘时想让某条只画动漫、另一条只画真人 | 「工作流模板」→「轮换顺序」列表每行单独选「可画类型」，选完点「保存」；没单独设的用「可画类型（整体默认）」 |
| 设了「只画动漫」却画出真人 / 老人 / 男人 | 先去「调试与日志 → LLM 试跑一次」看「可画类型」标签与最终正负向提示词：若没有 `anime style` 等硬标签，检查「提示词」页「画风硬锚定」是否开启；若已开启仍出真人，看模板行「生效」有没有底模错配提示（写实底模变不出二次元，需换动漫底模） |
| 出了全黑 / 纯色图 | 以前会被当成功存档，现在会写「输出疑似无效（几乎全黑…）」并换种子重试一次。连试两次都黑，基本是底模/VAE 不匹配或自定义节点没装（同一份工作流在 ComfyUI 界面里应该也黑） |
| 质检一直「跳过」 | 说明模型不支持图片输入或调用失败。把 `quality_guard.provider_id` 指到一个多模态模型；「调试与日志」的事件日志里会写具体原因 |
| 质检分数偏低、老是触发重画 | 先用图库的「试评分」看几张真实分数，把 `quality_guard.min_score` 调到略低于平均分（例如平均 72 就设 65），别一上来设 80 |
| 精修没生效 | 三件事：开关打开了吗、`refine.ckpt_name` 填的是 ComfyUI checkpoints 目录里的真实文件名吗、精修失败会在事件日志里写原因（失败会用原图，出图本身不受影响） |
| 采样参数档没效果 | 模板行的「警告」会写明哪些字段在该工作流的采样器上不存在（异形采样链常见），这些字段会被忽略，不会硬塞 |
| 提示词被截断 | `prompt.max_tags` 默认 75：SD1.5 只有 77 token，超出不生效。想看当前标签数去「调试与日志」的 LLM 试跑（会显示「标签 N」） |
| 半夜老是画夜景 | 时间一致性默认开、且「光照跟随时段」也开。想随机一点就去「生成服务 → 时间一致性」关掉「光照跟随时段」（时段硬规则仍保留），或直接关总开关 |
| 白天想画夜间场景 | 同上：关掉「光照跟随时段」，或在主题词池「高级 → 光色」里自己加想要的词（自定义词不受时段过滤） |
| 角色卡没生效 | 三件事：`character.mode` 不是 off 吗、卡片的「固定标签」填了吗（danbooru 风格才有前置标签）、自然语言风格只认简报里的角色名。用 `--char 名字` 可以绕过配置直接验证 |
| A/B 没有对比数据 | 需要同时打开「成图自检」（否则没有分数）；且 A、B 两版都要填、至少各出几张图后才有样本 |

`test_schema.py` 复刻了 AstrBot 装载期的 schema 解析规则（每个节点必须有合法 `type`、
`object` 必须有 `items`）—— 少一个 `type` 就会让插件装不上，且本地只测业务代码发现不了。

模块一览：`main.py`（生命周期 / 调度装配 / 指令 / 萌绘联动 / 画质流水线）、`scheduler.py`（调度判定与循环）、
`daylight.py`（日出日落估算 / 时段判定 / 光照池收窄 / 矛盾扫描，纯标准库）、
`prompter.py`（抽签 + 契约 + 尺寸）、`workflow_mgr.py`（模板加载 / 注水 / 轮换 / 底模画像）、
`comfy_client.py`（ComfyUI HTTP + 错误摘要）、`gallery_store.py`（sqlite + 归档 + LRU）、
`delivery.py`（投递）、`webui_api.py`（控制台接口）、`config_coerce.py`（配置读写纯函数）、
`errfmt.py`（错误文本兜底）。

控制台另有三个辅助接口：`/theme/pool`（内置词池全貌）、`/prompt/preview`（三种风格下当前生效的
系统提示词）、`/workflows/rotation/reset`（把顺序轮换重置到 #1）。`/workflows` 现在会附带
`rotation` 字段（有序可用名单与下一张）。
